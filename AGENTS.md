# Правила работы с Messanger

Сервер разрабатывается на Go. Версию языка, зависимости и структуру проверяй
по текущим `go.mod` и исходникам. Точка входа — `cmd/server`, SQL-миграции —
`database/migrations`; существующий SQL использует синтаксис PostgreSQL.
Не заменяй выбранный стек и не подключай параллельную серверную реализацию.

## Локальные навыки

Перед соответствующей задачей прочитай нужный `SKILL.md`:

- SQL-запросы и репозитории: [.agents/skills/sql-query-review/SKILL.md](.agents/skills/sql-query-review/SKILL.md).
- Схема и миграции: [.agents/skills/sql-migration-review/SKILL.md](.agents/skills/sql-migration-review/SKILL.md).
- Границы пакетов и бизнес-сценарии: [.agents/skills/go-clean-architecture/SKILL.md](.agents/skills/go-clean-architecture/SKILL.md).
- Общая память, goroutine, WebSocket и одновременные записи: [.agents/skills/go-concurrency-safety/SKILL.md](.agents/skills/go-concurrency-safety/SKILL.md).
- Уточнение требований и существенных противоречий перед сложной реализацией: [.agents/skills/grill-me/SKILL.md](.agents/skills/grill-me/SKILL.md).
- Архитектурный аудит и порученный рефакторинг существующего кода: [.agents/skills/improve-codebase-architecture/SKILL.md](.agents/skills/improve-codebase-architecture/SKILL.md).
- Разработка поведения по циклу Red → Green → Refactor: [.agents/skills/tdd/SKILL.md](.agents/skills/tdd/SKILL.md).
- Сущности, доменные операции и границы согласованности: [.agents/skills/domain-modeling/SKILL.md](.agents/skills/domain-modeling/SKILL.md).
- Передача контекста следующей сессии или агенту по запросу: [.agents/skills/handoff/SKILL.md](.agents/skills/handoff/SKILL.md).

Применяй навыки по затронутой области. Если изменение требует нескольких,
прочитай соответствующие инструкции; не запускай полный аудит для несвязанной
локальной правки. Прямой запрос пользователя определяет объём работы.

`go-clean-architecture` задаёт границы для текущего изменения,
`improve-codebase-architecture` помогает найти и устранить проблемы существующей
структуры. Не дублируй два полных аудита для одной задачи. `grill-me` нужен для
существенных неизвестных, а не как обязательный опрос перед каждой правкой.
При явном запросе на TDD используй `tdd`; простые изменения текста или метаданных
не требуют искусственного цикла Red → Green. Передача контекста сама по себе
не означает создание нового чата или отправку ему сообщения.

## Проверки и результат

Для изменений Go выполняй проверки, подходящие по риску: целевые тесты,
`go test ./...`, `go vet ./...`; при изменении конкурентного поведения —
`go test -race ./...`, если среда это поддерживает. SQL и миграции проверяй
на целевой версии PostgreSQL, когда доступен изолированный тестовый стенд.
Не скачивай новый toolchain и не меняй версию Go молча ради проверок.

В ревью сообщай подтверждённые дефекты с файлом, строкой, сценарием и последствием.
Разделяй ошибки, предположения и необязательные улучшения. Указывай, что проверено
исполнением и какие проверки недоступны. Запрос на ревью не требует изменения
исходников или применения миграций к рабочей базе.
